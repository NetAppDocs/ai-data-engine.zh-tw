= 將 AI Data Engine 連接到 Microsoft Entra ID，以實現受控 AI 存取
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
將 Microsoft Entra ID 連接到 AI Data Engine（AIDE）作為身分供應商，以便您可以透過模型上下文協定（MCP）驗證使用者，並控制他們可以使用的集合。身為 AI Data Engine 系統管理員，您需要設定身分供應商、設定 MCP 的集合，並在 NetApp Console 中驗證您的組態。

受監管的 AI 存取使用 Entra ID 來驗證使用者，您為每個集合包含的範圍決定了使用者可以透過 MCP 使用哪些集合。



[[before-you-begin]]
== 開始之前

* 您必須擁有 _AI Data Engine 系統管理員_ 角色。
* AI Data Engine 已部署並掃描了至少一個資料來源。請參閱link:../data-sources/connect-data-source.html["連接資料來源"]。
* AIDE 叢集主機名稱設定在已註冊的 DNS 網域上，該網域已在您的 Entra ID 租戶中驗證。請參閱 link:prepare-mcp-host.html["準備 MCP 主機"]。
* Microsoft Entra ID 系統管理員已為此 AI Data Engine 執行個體註冊了 AI Data Engine 應用程式，並向您提供了目錄（租戶）ID 和應用程式（用戶端）ID。請參閱 link:configure-entra-id-mcp.html["設定 Microsoft Entra ID 以進行受控 AI 存取"]。




[[set-up-an-identity-provider]]
== 設定身份供應商

將 Microsoft Entra ID 連接為身分識別供應商（IdP），以驗證和授權存取您的資料收集中的資料資源。

.開始之前
* 您必須擁有 _AI Data Engine 系統管理員_ 角色。
* 您擁有此 AI Data Engine 執行個體在 Microsoft Entra ID 中註冊的 AI Data Engine 應用程式的租戶 ID 和應用程式（用戶端）ID。


.步驟
. 在 NetApp Console 中，前往 *AI 資料中心* > *AI Data Engine*。
. 選取 *組態* > *身分供應商*。
. 選取 *新增身分供應商*。
+
*新增身分供應商*面板隨即開啟。

. 從 *選擇身分供應商* 中，選擇 *Microsoft EntraID*。
. 在 *Entra 租戶 ID* 中，輸入您的 Entra ID 租戶的目錄（租戶） ID。
. 在 *應用程式（用戶端）ID* 中，輸入 AI Data Engine 應用程式的應用程式（用戶端）ID。
+

IMPORTANT: 請輸入應用程式（用戶端） ID，該 ID 為 GUID。請勿輸入應用程式 ID URI。權杖透過 GUID 識別 AI Data Engine 應用程式，因此 URI 會導致登入失敗。

+
請使用 Microsoft Entra ID 組態中的識別碼。AI Data Engine 會檢查這兩個值的格式，並確認租戶是否存在。如果出現 *無效身分* 訊息，請驗證這些值並進行修正，然後再試一次。

. 選取 *新增身分供應商*。


設定完成後， AI Data Engine 會顯示確認訊息 *身分供應商已成功建立。*該供應商會出現在 *身分供應商* 清單中。在繼續操作之前，請確認其 *連線狀態* 為 *已連線*。

使用與 AI 用戶端中用戶端 ID 相同的應用程式（用戶端）ID。

對身分識別供應商和收集設定的變更可能不會立即生效，因為 NetApp Console 會非同步地將它們套用至 MCP 伺服器。

新增身分供應商不會自動將其與資料收集關聯。設定收集時，請選擇身分供應商，以便 AI 應用程式可以透過驗證和授權存取其資源。請參閱 <<configure-collections-for-mcp,為 MCP 設定集合>>。只有當沒有任何收集使用該身分供應商時，才能將其刪除。若要編輯，請參閱 link:maintain-mcp-setup.html#update-an-identity-provider["更新身分供應商"]。



[[configure-collections-for-mcp]]
== 為 MCP 設定集合

設定身分供應商並建立集合後，在 NetApp Console 中為 MCP 設定集合。您選擇可以存取集合的身分供應商與使用者範圍，然後為您的 AI 用戶端建立 MCP 伺服器 URL 或用戶端特定組態片段的複本。請參閱 link:manage-data-collections.html#configure-a-collection-for-mcp["設定 MCP 的集合"]。



[[verify-your-configuration]]
== 驗證您的組態

在使用者連線前，請確認下列各項均屬實。應用程式 ID URI、範圍、租戶 ID 和用戶端 ID 必須在 Entra ID、NetApp Console 和您的 AI 用戶端中完全相符。

*AIDE 叢集主機*

* AIDE 叢集主機名稱位於 Entra ID 中已驗證的網域中。
* 主機名稱由使用者機器解析。
* 主機提供用戶端電腦信任的憑證。
* MCP 伺服器的已知端點傳回預期回應。請參閱link:prepare-mcp-host.html#verify-the-host["驗證主機"]。


*Microsoft Entra ID*

* 已為此 AI Data Engine 執行個體註冊專用應用程式。
* 應用程式 ID URI 為 `\https://<host>/mcp/tools`。
* 此  `power_users` 作用域存在，且在清單中  `requestedAccessTokenVersion` 設定為  `2`。
* 每個 AI 用戶端都註冊了一個重新導向 URI，並且允許公用用戶端流程。
*  `AIDEPowerUsers`應用程式角色已指派給您的使用者。


*NetApp Console*

* Entra ID 身分供應商具有租戶 ID 和應用程式（用戶端）ID，其連線狀態為 *已連線*。
* 在「MCP 集合」>「MCP 設定」>「MCP 伺服器連線」下，「啟用與 MCP 的連線」已開啟。
* MCP 伺服器狀態為*執行中*。
* 此集合已針對 MCP 進行設定，使用身分供應商和 `power_users`範圍。
* 您已產生 MCP 程式碼片段。


*AI 用戶端*

* 您已將程式碼片段新增至 AI 用戶端。
* 用戶端 ID 是應用程式（用戶端）ID。
* 作用域為應用程式 ID URI 加上 `/power_users`。
* 登入一次後，會列出 AI Data Engine 工具。
