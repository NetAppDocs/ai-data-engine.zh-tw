= 了解 AI Data Engine
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AI Data Engine （AIDE） 是一種中繼資料智慧服務，可讓您對儲存在儲存設備系統上的結構化和非結構化資料具有可見度。AI Data Engine 會掃描您的儲存設備系統並建立檔案系統中繼資料目錄，以便您找出儲存設備最佳化機會、調查您的資料，並強制執行治理原則。



[[what-ai-data-engine-does]]
== AI Data Engine 的功能

AI Data Engine 會掃描您連接的資料來源，並建立可搜尋的中繼資料目錄，該目錄會在每次掃描週期中刷新。您可以從該目錄執行以下操作：

* *了解您的儲存設備。*查看您有多少資料、誰擁有這些資料以及這些資料儲存在哪裡。
* *回收容量。*尋找冷資料、陳舊資料和複製資料，並查看哪些資料擁有者持有最多這類資料，以便您知道該聯絡誰進行清理。
* *尋找存取風險。*識別具有開啟權限的目錄，以便您可以優先審查這些目錄。
* *調查和整理。*使用中繼資料過濾器尋找您關心的資料，為其加上標籤，並將您的條件儲存為原則，以便您持續監控。
* *對資料採取行動。*標記、歸檔、複本或刪除您已審查的檔案。
* *為 AI 準備資料。*讓您授權的 AI 用戶端搜尋您的中繼資料並對資料執行動作。




[[storage-optimization-and-data-lifecycle-management]]
== 儲存設備最佳化和資料生命週期管理

使用中繼資料來識別需要審查的資料，例如符合組織冷與過時閾值的檔案和複製檔案。在決定是否保留、標記、歸檔、複本或刪除資料之前，請先調查結果。

儲存設備最佳化見解指出了機會。您可能回收的容量取決於您選擇採取的行動。



[[governed-ai-access]]
== 受監管的 AI 存取

受控 AI 存取可讓 AI 用戶端透過模型上下文協定（MCP）在您設定的範圍內搜尋您的中繼資料。您可以透過建立集合來選擇要提供哪些資料。集合是您提供給 AI 用戶端的一組已掃描資料。您可以透過定義 Microsoft Entra ID 範圍來控制使用者可以搜尋哪些集合。

AI 用戶端只能處理中繼資料。無法擷取檔案內容。

link:../mcp/learn-about-mcp.html["了解更多關於受監管的 AI 存取"]。



[[who-uses-ai-data-engine]]
== 誰在使用 AI Data Engine

以下範例展示不同的人可能如何使用 AI Data Engine：

* *儲存管理員*需要審查符合其組織冷檔案和過時檔案閾值的檔案，識別複製檔案，並評估儲存設備最佳化機會。
* *IT 維運團隊* 需要集中檢視其儲存環境中存在的結構化和非結構化資料
* *資料或 AI 團隊成員*使用 AI 用戶端搜尋授權集合中的中繼資料，並標記他們想要處理的資料。
* *IT 主管* 正在推出 AI 工具，需要選擇 AI 用戶端可以搜尋哪些集合以及誰可以使用它們。




[[where-ai-data-engine-runs]]
== AI Data Engine 運作的位置

您可以透過 NetApp Console 存取 AI Data Engine，路徑為 *AI 資料中心 > AI Data Engine*。掃描與目錄服務會在您提供的基礎架構上執行，無論是在您的雲端帳戶或內部部署環境中。選擇在 Linux VM 上進行 AIDE 單節點部署，或者如果您的環境需要大規模的高可用度，則選擇在 Kubernetes 叢集上進行 AIDE 多節點部署。

link:../deploy/deployment-overview.html["了解更多部署選項"]。

AI Data Engine 會掃描您連線的支援資料來源。如需詳細資訊，請參閱 link:../data-sources/connect-data-source.html["連接資料來源"]。
